QUESTIONS AND ANSWERS

Frequently asked questions

Honest answers about how AgentGuard works, what protects it, and where it still falls short.

The basics
What is AgentGuard in one sentence?
A payment system where a client agent and a worker agent transact USDC on Arc autonomously — no human approving each individual transaction.
Is this real money?
No — this runs on Arc Testnet with test USDC. The goal is proving the pattern works before any real deployment.
Why hold funds in escrow instead of paying directly?
So the client has a real window to review the work before funds settle permanently with the worker — funds sit in a smart contract, not with either party.
Who decides if there's a disagreement?
An independent AI model reviews the dispute immediately, voted on three separate times with majority ruling. A rare tie routes to a password-protected admin dashboard for a human decision.
Latch — access control
What is Latch, and why does AgentGuard use it?
Latch is a policy-enforcement proxy from Subzero Labs (the team behind Rialo). Instead of the agent holding raw OpenAI or Circle API keys, every call passes through a Latch-scoped token that checks it against allowed limits first — endpoint allowlists, rate limits, spend caps — before the request ever reaches OpenAI or Circle.
What does Latch actually protect here?
Two separate policies: one for every OpenAI call in task.js (capped at 60 req/min, $5/day, specific models only), and one for Circle USDC transfers (capped at 10 USDC per transfer, 20 USDC/day). Each is independently scoped — a leak in one doesn't expose the other.
What's the actual benefit of Latch, if the system already works without it?
Blast-radius reduction. If a credential ever leaked, an unscoped key has no limit on the damage. A Latch-scoped token caps that damage to specific endpoints, small amounts, and rate limits. It's a defense-in-depth layer, not a functional requirement — the app would still run without it, just with a much larger risk if something went wrong.
Did building this surface anything useful about Latch itself?
Yes — two concrete technical notes found during integration: the correct live proxy URL format wasn't obvious from early examples, and Latch's numeric comparison filters don't coerce a numeric string into a number, which caused a working policy to always reject valid Circle transfer amounts until a regex-based filter was used instead.
Security and the smart contract
Is the smart contract audited?
No — it's built on OpenZeppelin's audited primitives (ReentrancyGuard, Ownable, Pausable), but the contract as a whole hasn't been reviewed by a professional security firm. Not intended for real funds yet.
What happens if the arbitrator or owner disappears?
forceRefund() is a safety valve: if a dispute sits unresolved for 7 days, anyone can call it to refund the client. Separately, the contract has an emergency pause the owner can trigger to block new jobs and releases immediately if a critical bug is ever found — without redeploying.
Can the AI arbitrator be manipulated or give inconsistent decisions?
A single AI call can occasionally flip its verdict on identical input — a known property of language models. To reduce this, the arbitrator is called three times independently per dispute, with tie-breaker rounds before falling back to manual review.
Relation to Rialo
Does AgentGuard resemble something Rialo already has?
Yes, notably. Rialo has its own framework called SCALE (Simple Contracts for Agent Labor Execution) that does essentially the same thing: escrow funds for a task, have an independent judge review the work, and auto-refund on missed deadlines. AgentGuard arrived at the same pattern independently, built on Arc/Circle instead of Rialo's own chain.
What's the practical value for Rialo's team?
A real, working test case for Latch in an "agent pays agent" scenario, independent validation that the SCALE-like pattern is workable outside Rialo's own chain, and concrete technical feedback on Latch's proxy format and payload filter behavior.
Honest limitations
What's not finished yet?
The daily spend cap is shared across all visitors, not per-user. Only one worker agent exists today, though wallet-linked reputation is ready for more. The contract still needs a professional audit before handling real funds.
If it's not production-ready, what's the point?
To demonstrate a working, tested proof of concept — real transactions on Arc Testnet, verified end-to-end, with every design decision documented honestly. It shows the pattern works, not that it's finished.
