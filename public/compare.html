WHY THE HARDENING MATTERS

A naive system vs. AgentGuard

Every row here closes a real gap that a simple "agent pays agent" system would leave open.

LayerNaive systemAgentGuard
Credentials Raw API keys, unlimited blast radius Latch-scoped, rate-limited, spend-capped
Verification Same model grades its own work Independent model reviews every result
Escrow None — direct payment on completion On-chain smart contract holds funds
Disputes No recourse once paid 30s window, AI arbitration by majority vote
Stuck funds No fallback if a party disappears forceRefund() after 7-day timeout
Critical bug No way to stop the system Owner-controlled emergency pause
Reputation Resets every redeploy Persistent, wallet-linked track record
Per-user wallets Everyone shares the same wallet and balance Sign in with Google for your own isolated wallet
User-to-user transfers No way to send funds to another user directly Send USDC to any signed-in user, wallet-based and rate-limited

None of this makes AgentGuard production-ready — the contract is still unaudited, and other honest limitations remain (see the FAQ). But each row above is a real gap that was identified and closed, not a theoretical concern.
